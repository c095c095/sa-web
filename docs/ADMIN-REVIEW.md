# ตรวจรับส่วนจัดการและการเดินงานใหม่

8 พฤศจิกายน 2569 · ดำเนินการตามแผน ADMIN-EXTENSION-PLAN.md ที่ผู้ใช้อนุมัติ พร้อมข้อกำหนดว่าให้ลดความยากในการเดินแต่ละขั้น ไม่เพิ่มภาระที่ช่องกรอก

## เริ่มใช้

เปิด http://127.0.0.1:3000/login บัญชีพนักงานสมมติเดิมอยู่ใน `.local/LOGIN.md`

**ผู้ดูแลระบบครั้งแรก:** เปิด `.local/ADMIN-SETUP.md` แล้วกดลิงก์ในไฟล์ กรอกชื่อที่แสดงและตั้งรหัสผ่านของคุณ บัญชีเข้าใช้คือ `ADMIN` รหัสตั้งค่าจากไฟล์จะกรอกให้เองและใช้ตั้งบัญชีได้ครั้งเดียว ไม่มีการนำชื่อสมาชิก/หัวหน้ากลุ่มในรายงานมาสร้างบัญชีแทนผู้ใช้

พนักงานที่สร้างใหม่ได้รับรหัสบัญชีและรหัสชั่วคราวจากแอดมิน เมื่อเข้าครั้งแรกจะให้ตั้งรหัสของตน แล้วไปหน้างานต่อได้ทันที การเข้าสู่ระบบเก่าถูกเพิกถอนและใช้ session ใหม่

เมื่อต้องทดลองหลายฝ่ายพร้อมกัน ให้ใช้คนละโปรไฟล์เบราว์เซอร์หรือคนละเบราว์เซอร์ เพื่อไม่ให้บัญชีแทนกันใน session เดียว

## สิ่งที่เปลี่ยนในการใช้งาน

- หน้าหลักพนักงานเริ่มที่ **งานของฉัน/ทะเบียนบ้าน** ไม่แสดงเมนูย่อยทั้งกระบวนการให้ไล่เลือกเอง
- เปิดบ้านครั้งเดียวแล้วเห็น **งานที่ทำได้ตอนนี้** และฝ่ายที่กำลังรอ เลือกงานแล้วบริบทบ้าน/จุดติดไปกับขั้นถัดไป
- ช่างเปิดงานจากรายการ เห็นรายละเอียดแล้วกด **รับงานนี้** ได้ ไม่มีช่องค้นหาหรือเลือกงานเดิมซ้ำในหน้าที่เปิดเจาะจงงานมาแล้ว
- หลังบันทึก แสดง **ทำอะไรต่อ** พร้อมปุ่มขั้นถัดไป หรือบอกว่ารอฝ่ายใด ไม่ทิ้งไว้ที่ฟอร์มของขั้นที่เสร็จแล้ว
- รายการที่มีงานให้เลือกเพียงรายการเดียวเลือกให้แล้ว ไม่ต้องเลือกซ้ำในช่องรายการ
- ลูกค้าแจ้งจุดเพิ่มได้ต่อเนื่อง แล้วกด **แจ้งครบแล้ว ติดตามการซ่อม** หากเพิ่งเปิดรอบและยังไม่มีจุด แยกทางแจ้งจุดกับยืนยันตรวจครบไม่พบจุดให้ชัด
- ลิงก์งานเก่าหรือไม่พบงานไม่แทนที่ด้วยงานอื่น ต้องกลับดูงานล่าสุด ป้องกันรับ/ซ่อม/จัดประเภทผิดงาน

## ส่วนจัดการที่ใช้งานได้

| เมนู | ความสามารถ |
|---|---|
| ภาพรวม | สถานะบ้าน งานค้าง โครงการ/บัญชีที่เปิดใช้ นัดหมายจริง และลิงก์ไปทะเบียนตามตัวกรอง |
| โครงการ | เพิ่ม เปลี่ยนชื่อ ปิด/เปิดรับบ้านใหม่ งานเดิมยังทำต่อได้ |
| บ้าน | ค้นหา กรอง เรียง แบ่งหน้า เพิ่ม/แก้ข้อมูล เก็บเข้าคลัง/นำกลับ ดูประวัติ จุด คำขอ เอกสาร/รูป/ลายเซ็นจริง ผูกลูกค้าก่อนเริ่มตรวจ |
| ลูกค้า | เพิ่ม ค้นหา แก้ข้อมูลที่อนุญาต ดูบ้านที่ผูก ซ่อนเลขประจำตัวส่วนใหญ่ในรายการ |
| พนักงาน | สร้างบัญชี สิทธิ์/ประเภทช่าง เปิด/ปิด รีเซ็ตรหัส โอนงานค้างอย่างชัดเจนก่อนปิด/เปลี่ยนสิทธิ์ |
| ลิงก์ลูกค้า | ออกลิงก์ 30 วันใหม่ ดูวันหมดอายุ เพิกถอนพร้อม session ที่ใช้ลิงก์นั้น |
| การเข้าสู่ระบบ | ดูรายการที่ยังเปิดอยู่และเพิกถอน |
| ประวัติการจัดการ | ใครแก้อะไร เหตุผล ก่อน/หลัง และเวลา โดยไม่เก็บรหัสผ่าน/token/เลขประจำตัวเต็ม |
| บัญชีของฉัน | โปรไฟล์ ข้อมูลติดต่อ เปลี่ยนรหัส ออกจากระบบรายการอื่น ลูกค้ายังใช้ลิงก์และแก้เฉพาะข้อมูลติดต่อ |

แอดมินเป็นบัญชีส่วนจัดการเฉพาะ ไม่ได้อนุมัติ QC รับงานช่าง หรือเซ็นแทนลูกค้า การเปลี่ยนเลขบ้าน/โครงการถูกจำกัดหลังมีประวัติ เปลี่ยนลูกค้าทำได้ก่อนเริ่มตรวจและต้องเพิกถอนสิทธิ์เดิม ปิดแอดมินคนสุดท้ายไม่ได้รวมกรณีทำพร้อมกัน

## DoR / DoD / ECC และผลตรวจ

DoR: แผนและบัญชีแอดมินเฉพาะรับแล้ว มี backup ก่อน migration ใช้ DB ทดสอบแยก backfill โครงการจากข้อมูลเดิมโดยไม่เดาชื่อหรือรวมรายการที่คลุมเครือ

DoD ภายใน: สร้าง/แก้ข้อมูลและ reload พิสูจน์กับ DB ได้ บังคับเปลี่ยนรหัส เพิกถอนสิทธิ์ทันที มี audit ใน transaction เดียว ป้องกัน stale update/last-admin/concurrent action งานเดิมยังทำได้ และตรวจหน้าจอ/keyboard/contrast ตาม evidence

ECC: หากพบข้ามสิทธิ์ ข้ามบ้าน รับผิดงาน หรือเปลี่ยนข้อมูลบางส่วน ให้หยุดเส้นทางที่กระทบและเก็บกรณีทำซ้ำก่อนเปิดต่อ ไม่ลบประวัติหรือแก้ผลตรวจให้ข้ามขั้น ไม่ส่งอีเมลหรืออ้างว่ามีช่องทางส่งรหัสอัตโนมัติที่ยังไม่ได้เชื่อม

หลักฐานจริงอยู่ใน `evidence/runtime-integration.json`, `runtime-browser.json`, `runtime-active-visual.json`, `management-integration.json`, `management-stale-task.json`, `management-hallmark.json` และ `management-summary.json` อ่านจำนวน/สถานะจาก run สุดท้าย ไม่ใช้ expected หรือข้อมูล PGlite เก่าแทน

Runtime เพิ่ม `project`, `app_control`, `audit_event` และข้อมูลสิทธิ์/version/archive/revocation ใน migration `003-management.sql` แยกเป็น EXT-ACC/EXT-ADM จาก 18 UC เดิม ไม่แก้ schema/contract/รายงาน SA ต้นฉบับ

## ให้ลองตรวจ

1. ตั้งแอดมินจากลิงก์ในไฟล์ส่วนตัว เพิ่มโครงการ/บ้าน/พนักงาน แล้วให้บัญชีใหม่เข้าตั้งรหัสเอง
2. พนักงานเปิดบ้านหรืองานจากหน้าแรก แล้วใช้ปุ่มทำต่อจนส่งต่องานให้อีกฝ่าย โดยไม่ไล่หา SCR/UC หรือเลือกบ้านซ้ำ
3. ลองเปลี่ยนข้อมูลส่วนตัว รีเซ็ตรหัส เพิกถอนลิงก์ และดูประวัติรายการที่แก้ไข

สถานะ: พร้อมให้ผู้ใช้ตรวจส่วนจัดการและความง่ายในการเดินงานที่ A5 จากนั้นจึง P6 recovery/restore/UAT/final delivery ตามแผน ไม่ถือว่าผ่านการตรวจรับโดยผู้ใช้หรือพร้อม public deployment จากผลอัตโนมัติเพียงอย่างเดียว
