# ระบบตรวจและส่งมอบบ้าน

เว็บไซต์ในโปรเจกต์เดิม บันทึกข้อมูลได้จริงตาม 18 use case บน Next.js และ MariaDB ใน XAMPP ใช้ข้อมูลตั้งต้นสมมติแยกจากข้อมูลโครงการจริง

- [เข้าสู่ระบบพนักงาน](http://127.0.0.1:3000/login)
- [เข้าใช้ผ่านลิงก์ลูกค้า](http://127.0.0.1:3000/access)
- [ตั้ง Demo Mode บนเครื่องอื่นและลำดับสาธิต](docs/DEMO.md)
- บัญชีทดสอบและรหัสผ่านอยู่ใน `.local/LOGIN.md` เฉพาะเครื่องนี้
- [วิธีเปิดระบบและขอบเขตการทดสอบ](docs/RUNTIME.md)
- [รายการตรวจรับ G2](docs/G2-REVIEW.md)
- [ส่วนจัดการและวิธีเดินงานใหม่](docs/ADMIN-REVIEW.md)
- ผู้ดูแลครั้งแรกเปิด `.local/ADMIN-SETUP.md` แล้วตั้งชื่อ/รหัสผ่านของตน บัญชี `ADMIN` ไม่ได้สร้างจากข้อมูลสมาชิกในรายงาน
- [ข้อปรับทางเทคนิคที่รับที่ G1](docs/TECHNICAL-AMENDMENTS.md)

ใช้ Next.js + TypeScript + Tailwind CSS + daisyUI ธีม Furrow และ MariaDB ใน XAMPP

หน้า `/` แสดงภาพรวมตามบทบาทและขั้นตอนถัดไป เมนูงานเปิดหน้ารายการตามชื่อ เช่น `/customer-access` หรือ `/repairs` ให้เลือกบ้านหรืองานซ่อมก่อนเปิดหน้าดำเนินการ ลูกค้าดูสรุปสถานะ รูปประกอบ และ PDF ที่มีของบ้านตนจากเมนูติดตามสถานะการซ่อม

เมนู `/admin/<section>` จัดการโครงการ บ้าน ลูกค้า พนักงาน ลิงก์และประวัติ ส่วน `/account` จัดการบัญชีตนเอง

หน้า `/pilot/*` เดิมส่งต่อเข้าสู่ระบบแล้ว หลักฐาน P1 ใน `README-P1.md` และ `docs/P1-REVIEW.md` เป็นบันทึกในเฟสก่อนหน้า ดูสถานะล่าสุดจากเอกสาร G2
